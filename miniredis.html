MiniRedis

High-Concurrency C++ Key-Value Store with Asynchronous MySQL Persistence

C++ MySQL Winsock2 Multithreading System Architecture

Statistics

  • Started March 2026
  • Status Stable
  • GitHub Repo

Description

Background

In-memory data stores offer unparalleled speed but suffer from volatility during system failures or server restarts. To deeply understand the internal mechanics of enterprise caching engines like Redis, I architected a high-concurrency, multithreaded key-value store from scratch to bridge the gap between microsecond-level memory access and durable disk storage.

Solution

Developed a custom, multithreaded LRU (Least Recently Used) cache in C++, tightly integrated with a MySQL persistence layer. By strictly isolating network I/O from database syncs using a core-locked thread pool, the system achieves instant RAM-level speeds while guaranteeing robust data durability and zero data races under heavy load.

Core Features

To combat the volatility of pure memory storage, the architecture features:

  • O(1) LRU Cache: Engineered using a Hash Map paired with a custom Doubly Linked List, enabling ultra-fast ~3 µs read latencies for cache hits.
  • Affinity-Locked Thread Pool: Bound strictly to 4 physical CPU cores to eliminate OS context-switching overhead while handling concurrent client TCP connections (Winsock2).
  • Asynchronous Persistence: Implemented a write-behind mechanism where PUT commands update RAM instantly, while offloading low-priority database syncs to background workers to prevent blocking the main thread.
  • Thread Safety: Utilized fine-grained locking via std::mutex and std::condition_variable to safely manage task priority queues and concurrent memory evictions.
  • Seamless Disk Fallback: Automatically resolves cache misses by querying MySQL and loading the missing key into RAM, resolving in ~868 µs.

Learning Outcomes

Building this required strict adherence to fundamental C++ memory management, network socket programming, and concurrency control. It heavily solidified my understanding of database persistence pipelines, thread prioritization, and the real-world complexities of safely synchronizing volatile cache layers with disk storage without sacrificing latency.
